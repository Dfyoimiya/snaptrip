# 时间协商

## 触发条件

- 用户输入时间模糊（"下午"、"周末"、"最近有空"）
- 系统生成的时间与商户营业时间冲突
- 用户拒绝初始时间建议

## 执行步骤

1. 解析用户输入中的时间信号词
2. 若解析失败，默认设置为"从现在开始，4 小时内"
3. 若发现首选时段 POI 不可用，执行时间推算：
   - 计算下一个可用时段
   - 检查替代时段是否仍有足够数量的 POI
4. 若无法找到完全匹配，向用户推送「时间调整建议」
5. 用户确认后，以新时间重新执行规划

## 示例

### 输入
> "下午去喝茶"

### 解析过程
```
当前时间: 13:30
下午 = 13:30 ~ 18:00
默认窗口: 简化为此范围内
若目标茶馆 15:00~17:00 客满 → 推荐 13:30~15:00 或延迟至 14:30~16:30
```

### SSE 推送
```
event: time_negotiate
data: {
  "original": "15:00~17:00",
  "suggestion": "13:30~15:00",
  "reason": "15:00~17:00 该茶馆客满",
  "alternatives": ["14:30~16:30"]
}
```
